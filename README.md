# Проект аналитика 1С

Шаблон проекта аналитика 1С для работы с ИИ-агентом. У сырья, знаний, решений,
спецификаций и пакетов здесь свои места, а агент получает правила работы с ними
в `AGENTS.md`. Задача ведётся от встречи с заказчиком до согласованного пакета и
спецификации для разработки, знания о системе копятся в wiki, решения
фиксируются записями ADR.

Навыки агента и установка инструментов лежат в отдельном репозитории
[1c-analyst-workplace](https://github.com/Romandredan/1c-analyst-workplace):
рабочее место ставится один раз на компьютер, а проектов из этого шаблона может
быть сколько угодно.

## Где что лежит

| Место | Что лежит | Кто пишет |
|---|---|---|
| `AGENTS.md` | Правила агента в этом проекте | Владелец проекта |
| `docs/research/` | Сырьё задач: письма, транскрипты, ответы заказчика | Внешний мир; не переписывается |
| `wiki/` | Как устроены система и процессы | Агент по правилам `wiki/AGENTS.md` |
| `docs/adr/` | Почему решили так | Аналитик с агентом, подтверждает владелец |
| `memory/` | Как здесь работать: договорённости и уроки | Агент по правилам `memory/README.md` |
| `openspec/` | Что меняем: спецификации изменений | Аналитик с агентом |
| `deliverables/` | Пакеты на согласование и для разработки | Навык `analyst-handoff` |
| `src/` | Код конфигурации | Команда разработки; агент читает через индекс |
| `setup/` | Подключение инструментов и версии | Навык `analyst-workplace-setup` |
| `tools/hooks/` | Хуки памяти проекта для клиента агента | Шаблон |
| `.zcode/`, `.mcp.json`, `.claude/` | Подключение MCP и хуков для ZCode и Claude Code | Шаблон |

## Как работает проект

```text
сырьё и встречи → извлечение требований → ответы заказчика → ADR и прожарка
  → пакет для заказчика (подпись) → изменение OpenSpec → пакет для разработки
```

| Вопрос | Место | Навык |
|---|---|---|
| Что сказал заказчик | `docs/research/<кейс>/` | `requirements-elicitation-ru` |
| Как устроено | `wiki/` | Правила `wiki/AGENTS.md` |
| Почему решили так | `docs/adr/` | `brainstorming`, `domain-modeling`, `grilling` |
| Как здесь работать | `memory/` | Хуки памяти проекта |
| Что согласовано с заказчиком | `deliverables/<кейс>/customer/` | `analyst-handoff`, `mermaid-diagrams-ru`, `md-design-prototype` |
| Что меняем | `openspec/changes/` | `openspec-propose` |
| Что передаём разработке | `deliverables/<кейс>/dev/` | `analyst-handoff` |

## Создать проект

**Новый репозиторий.** Кнопка «Use this template» на GitHub создаёт репозиторий
проекта без истории шаблона. Без GitHub:

```powershell
git clone https://github.com/Romandredan/1c-analyst-bootstrap.git vip-primerka
cd vip-primerka
git remote rename origin template
```

Затем заполните места шаблона:

```powershell
python tools/init_project.py --name "VIP-примерка" --system "Управление торговлей 11.5" --code-alias ut
```

Скрипт впишет имя, систему и алиас индекса и перечислит места, которые остались
пустыми: назначение проекта в `AGENTS.md` и разделы wiki в `wiki/index.md`.

**Существующий репозиторий команды.** Если разработка уже ведёт репозиторий
(например, созданный из
[vanessa-bootstrap](https://github.com/vanessa-opensource/vanessa-bootstrap)),
аналитическая структура накладывается поверх него:

```powershell
python tools/init_project.py --into D:\work\team-repo --name "VIP-примерка" --system "Управление торговлей 11.5" --code-alias ut
```

Существующие файлы не перезаписываются, скрипт перечислит пропущенные. Тогда
`src/` принадлежит команде, а правка аналитика идёт на ревью разработчику.

## Подключить инструменты

1. Рабочее место: навык `analyst-workplace-setup` из
   [1c-analyst-workplace](https://github.com/Romandredan/1c-analyst-workplace).
2. Индекс кода, MCP и хуки клиента агента: [`setup/README.md`](setup/README.md).
3. Версии инструментов записываются в `setup/versions.md`.

## Обновления шаблона

Изменения шаблона перечислены в [CHANGELOG.md](CHANGELOG.md). Проект, созданный
через `git clone`, забирает их из удалённого репозитория `template`:

```powershell
git fetch template
git merge template/main
```

Проект, созданный кнопкой «Use this template», общей истории с шаблоном не имеет:
нужные изменения переносятся вручную по CHANGELOG. Заполненные файлы
(`AGENTS.md`, `wiki/index.md`) при слиянии могут конфликтовать: в них
сохраняется версия проекта, а из шаблона берутся новые правила.
